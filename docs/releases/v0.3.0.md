# v0.3.0 Release Notes

**Release Date:** 2026-06-20

## Highlights

- Product catalog modeling with Capability and Feature entities
- Replace Project entity with Product for clearer domain modeling
- CLI tooling for capability catalog management
- JSON Schema generation from Go types

## Breaking Changes

### Project Renamed to Product

The `Project` entity has been renamed to `Product` throughout the codebase:

- Database: `project_id` columns renamed to `product_id`
- API: `project_id` field renamed to `product_id` in event payloads
- Ent schemas: `Project` entity replaced with `Product`

**Migration:**

Update your SDK integration to use `product_id` instead of `project_id`:

```diff
- "project_id": "proj_demo"
+ "product_id": "prod_demo"
```

## What's New

### Product Catalog Model

New entities for modeling product capabilities and features:

```
Organization
    └── Product
        └── Capability (major functional areas)
            └── Feature (specific functionality)
                └── Journey (user flows)
```

| Entity | Description |
|--------|-------------|
| **Product** | Replaces Project, represents an application being tracked |
| **Capability** | Major functional area within a product (e.g., "User Management") |
| **Feature** | Specific functionality within a capability (e.g., "Password Reset") |

### Ent Schema Changes

```go
// New Product entity with capabilities edge
edge.To("capabilities", Capability.Type)

// Capability with features edge
edge.To("features", Feature.Type)

// Journey can now link to a Feature
edge.From("feature", Feature.Type).
    Ref("journeys").
    Field("feature_id").
    Unique()
```

### Capability Catalog Types

New Go types for importing/exporting capability definitions:

```go
type CapabilityCatalog struct {
    Metadata     CatalogMetadata `json:"metadata"`
    Capabilities []Capability    `json:"capabilities"`
}
```

### CLI Tools

Three new CLI tools for catalog management:

| Tool | Purpose |
|------|---------|
| `schemagen` | Generate JSON Schema from Go types |
| `catalog2md` | Convert capability catalog to markdown |
| `catalogctl` | Validate and convert catalogs |

#### catalogctl Commands

```bash
# Validate catalog against JSON schema
catalogctl validate catalog.json

# Convert between JSON and YAML
catalogctl convert catalog.json -o catalog.yaml
catalogctl convert catalog.yaml -o catalog.json
```

### JSON Schema

Embedded JSON Schema for capability catalog validation:

```go
import "github.com/plexusone/productgraph/schema"

// Use embedded schema for validation
schemaBytes := schema.CapabilitySchemaJSON
```

## Upgrading from v0.2.0

### Required Changes

1. **Update event payloads**: Change `project_id` to `product_id` in all event submissions
2. **Database migration**: Run ent migrations to rename columns

### Database Migration

```bash
# Generate and apply migrations
go run -mod=mod entgo.io/ent/cmd/ent generate ./ent/schema
make migrate
```

### API Changes

```diff
POST /v1/events
{
  "events": [{
    "event_id": "evt_001",
-   "project_id": "proj_demo",
+   "product_id": "prod_demo",
    "session.id": "sess_001",
```
